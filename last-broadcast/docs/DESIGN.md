# LASTBROADCAST 设计文档

## 1. 核心创意
末日题材 × 电台值班员：玩家不是英雄、不是指挥官，而是『一台还在响的收音机』。
叙事核心是陪伴：选择播什么歌、说什么话、接谁的电话，本质是在决定以什么姿态陪一座城市走完最后一夜。

## 2. 玩法结构
- 12 个回合，22:00 → 次日 22:00：前 11 幕每 2 小时一幕，最后一幕跨 4 小时到终局的 22:00。
- 每回合一个动作：歌曲 / 播报（安抚·中立·真相）/ 来电 / 信号 / 沉默；第 12 幕只有"最后发言"（引擎会拒绝其他动作）。
- 单次游玩约 6~10 分钟；9 种结局（含 1 个隐藏结局），重玩价值来自选择而非随机。

## 3. 仿真模型
- 城市状态：hope（希望）与 mood（氛围），0~100，由动作效果累计。
- 你的精力：djStamina 0~100（初始 70）。歌曲 -3、播报 -5、来电 -4、信号 -6、沉默 +10；<30 时动作效果打折（歌 ×0.6 / 播报 ×0.7 / 来电 ×0.8 / 军队 ×0.7），<25 触发疲惫提示，归零再 -3 希望并留痕。
- 听众：15 名角色各有心情值与喜好标签；歌曲通过标签匹配影响个体（每命中一个标签 +2，正向歌曲再 +1），匹配结果按曲目缓存。
- 点歌联动：来电带 request 时记录 pendingRequest，下一回合放对应歌获得 +6 心情 +2 希望；放了别的歌留下一句叹息；还没兑现就被新来电顶掉也会留痕。
- 未接来电：双来电回合（04:00/10:00/16:00/18:00，索引 T3/T6/T9/T10）未接的电话会写入错过剧情。
- 关键旗帜：lullaby / nostalgic / truthCount / professorMet / signalDecoded / laozhouHonored / veteranHonored / silenceCount / requestsFulfilled 等驱动结局。
- 确定性：引擎无随机数，同一剧本必然同一结局（意外插曲变体由种子哈希决定）。
- 边界防护：军队切频与 FREQUENCY X 只能在各自回合处理；终局动作只能在第 12 幕执行——越界动作一律返回 error，不会写出越界日志。

## 4. 结局判定（9 种，按 computeEnding 的真实顺序）
1. 终局沉默 或 hope<20 → 尘埃
2. 隐藏：已集齐 6 个基础结局 + 终局非沉默 + hope≥40 → 纪念日
3. 终局希望 + 从未沉默 + hope≥75 → 不灭的电波
4. 终局希望 + 已解码 + 未放摇篮曲 → 灯塔
5. 终局希望 + 摇篮曲 + hope≥50 → 黎明歌谣
6. 终局真相 + 已解码 + 摇篮曲 → 黎明之后
7. 终局真相 + 已解码 → 信号
8. 终局陪伴 + 摇篮曲 + 接小雨与双胞胎 → 夜莺
9. 终局陪伴 + 接老周或老兵 → 火光
兜底：陪伴→(hope≥50?火光:尘埃)；希望→(hope≥50?黎明歌谣:火光)；真相→(已解码?信号:hope≥50?火光:尘埃)。

## 5. 节奏设计（情绪曲线）
- 前 4 回合：建立关系（来电密集、轻音乐、点歌）。
- 第 6 回合（08:00）：军队切频——外部压力第一次降临。
- 第 10 回合（16:00）：温教授的 FREQUENCY X 来电。
- 第 11 回合（18:00）：FREQUENCY X 解码 + 告别来电（老周/老兵二选一）。
- 第 12 回合（22:00）终局：希望 / 真相 / 陪伴 / 沉默，四选一对应九种结局。

## 6. 音频
- 电台底噪（白噪 + 50Hz 嗡鸣）常驻，强度随剧情起伏（军队切频最吵、停电后最安静）。
- 每首歌一份曲谱（scores.js：bpm / 四小节和弦进行 / 16 拍旋律 / 音色 / 鼓点），音序器用 lookahead 调度 64 个 16 分音符；和弦用 pad 层、低音、旋律、鼓点分别发声。
- 环境音层（带通噪声 + LFO）按回合切换；VU 表与示波器由 AnalyserNode 实时驱动。
- 生命周期：AudioContext 只在首次用户交互后创建；挂起后再次使用会自动 resume；每个音符的节点在 onended 时断开，鼓点噪声 buffer 与曲谱展开结果缓存复用。

## 7. 测试策略（62 项，node test/run.js）
- 数据完整性：ID 唯一、来电者与点播歌曲引用存在、双来电回合存在、点播来电数量、支线角色存在、隐藏结局基准一致。
- 引擎行为：回合推进、军队自动接管、X 信号锁定与回合限制、点歌加成与顶替留痕、未接来电、精力与疲惫提示、终局动作边界、存档校验、歌曲-听众匹配等价性。
- 九种结局分别用脚本化剧本验证可达性。
- 极端序列：固定种子随机跑 200 局 × 14 步（含非法动作），断言不抛异常、数值不越界、日志时段合法。
- 确定性：同剧本两次游玩结果 deepStrictEqual。
- 音频：用假 Web Audio 断言上下文恢复、音量/底噪记忆、节点回收、buffer/曲谱缓存、无 AudioContext 时的降级。
- 前端：用最小 DOM 桩按 index.html 顺序加载 6 个脚本，真实点击跑完一整夜，覆盖结局页、存档继续、成就提示、歌单与隐藏曲、灰按钮。
