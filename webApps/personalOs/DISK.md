# DISK.md · 虚拟磁盘格式与伙伴服务器

personalOs 的"硬盘"是一块 256 KiB 的虚拟磁盘，镜像是项目目录里的 `disk/disk.img`。
浏览器内核负责文件系统逻辑，一个零依赖的小服务器（`server/disk-server.mjs`）只做"硬盘控制器"，
按块或按整镜像转手数据。

## 物理布局

- 容量：512 块 × 512 字节 = 262 144 字节
- 字节序：小端（little-endian）
- 结构：FAT-lite（为浏览器内核定制的极简 FAT）

| 块号 | 用途 |
| --- | --- |
| 0 | 超级块（身份证 + 几何参数 + 脏位 + 校验和） |
| 1 - 2 | FAT 表（每块一个 u16 表项，2 块共容纳 512 项） |
| 3 | 保留的"引导区"（全部 0xFF 占位） |
| 4 起 | 数据区：从根目录开始，根目录可随内容增长搬迁 |

FAT 表项语义：`0x0000` = 空闲；`0xFFFF` = 链尾；其余值 = 下一块块号。
块 0 至 4（超级块、FAT、保留区、根目录首块）在格式化时即标记为链尾。

## 超级块（块 0）

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | magic | 固定 `POSDISK1` |
| 8 | 2 | version | 格式版本（当前 1） |
| 10 | 2 | blockSize | 512 |
| 12 | 4 | blockCount | 512 |
| 16 | 4 | fatStart | FAT 起始块（1） |
| 20 | 2 | fatBlocks | FAT 占用块数（2） |
| 24 | 4 | rootDirBlock | 根目录首块（初始 4，可迁移） |
| 28 | 4 | rootDirSize | 根目录字节数 |
| 32 | 4 | freeBlocks | 空闲块计数（fsck 会核对） |
| 36 | 1 | flags | bit0 = 脏位（挂载置位，正常关机清除） |
| 40 | 8 | installTime | 装机时间（毫秒，float64） |
| 48 | 8 | lastMount | 最近挂载时间（毫秒，float64） |
| 56 | 32 | label | 卷标（UTF-8，补零） |
| 88 | 4 | checksum | FNV-1a 校验和（覆盖 0 至 87 字节） |

## 目录项（128 字节）

目录是一个"条目数组文件"，占用若干数据块，每 128 字节一个条目：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | type | 1 = 文件，2 = 目录 |
| 2 | 1 | nameLen | 名字字节数（≤ 100） |
| 4 | 4 | size | 文件：字节数；目录：条目区字节数 |
| 8 | 2 | firstBlock | 首个数据块（空目录/空文件为 0） |
| 10 | 4 | created | 创建时间（Unix 秒） |
| 14 | 4 | modified | 修改时间（Unix 秒） |
| 18 | 110 | name | UTF-8 文件名（不含斜杠） |

规则：

- 文件名最长 100 字节（UTF-8），不允许空、`.`、`..` 或含斜杠
- 目录可以先"少占块"再增长；写入时整目录打包，按需增删块并把新首块写回父目录
- 根目录永远保留至少一个块：超级块必须始终能指向它
- 每次写操作按"数据块 → FAT → 目录 → 超级块"的顺序落盘，任何时刻的镜像都自洽

## 一致性：脏位与 fsck

- 挂载时置脏位；正常关机（关机/重启菜单）时清除
- 启动时若发现脏位，自动运行 `fsckRepair`
- `fsck` 采用"抢救重建"策略，而不是原地修补：
  1. 宽容遍历（chainSafe：断链截断、防环、防越界）收集所有可达的文件/目录内容
  2. 重新格式化同一块盘（保留卷标与装机时间）
  3. 把抢救内容按原路径写回，清除脏位
- 因此修复是幂等的：干净盘再跑一次不会产生任何变化
- `fsckAnalyze` 报告的问题类型：`magic`、`geometry`、`checksum`、`dirty`、`fat-reserved`、
  `fat-link`、`cycle`、`chain`、`cross-link`、`orphan`、`entry`、`size`、`free-count`、`root`

## 伙伴服务器 API（`server/disk-server.mjs`）

开发模式（Vite 中间件）与生产模式（`server.js`）共用同一个处理器，作用于目录 `disk/`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/hello` | 能力握手：`{ ok, name, version, size }` |
| GET | `/api/disk` | 读整个镜像；响应头 `x-disk-sha` 为 sha256 前 16 位十六进制 |
| PUT | `/api/disk` | 写整个镜像。校验尺寸（必须 262 144）与 magic；可选 `x-disk-sha` 乐观锁 |
| GET | `/api/disk/status` | `{ exists, size, mtime, sha, backups }` |
| GET | `/api/disk/backups` | 备份列表（名称、大小、时间） |
| POST | `/api/disk/restore` | 回滚到指定备份，`{ name }` 只接受 `^disk-[\w.-]+\.img$` |

写入协议细节：

- 每次写盘前，旧镜像轮转为 `disk/backups/disk-YYYYMMDD-HHmmss.img`，最多保留 8 份
- 新镜像先写临时文件再 rename，避免断电留下半个镜像
- 带 `x-disk-sha` 且与当前不一致时返回 `409`（前端会暂停自动保存并提示"重载"）
- 尺寸不对返回 `400`，magic 不匹配返回 `400`，非法的 restore 名称返回 `400`
- 超过容量上限的请求返回 `413`


## 备份与导入导出

- 设置应用支持：导出当前镜像为文件、导入镜像文件替换整个磁盘、一键回滚备份
- 格式化会重新装机并刷新页面；静态托管模式下导出/导入依然可用（本地暂存镜像）
