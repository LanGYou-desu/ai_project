# LASTBROADCAST 设计文档

## 1. 核心创意
末日题材 × 电台值班员：玩家不是英雄、不是指挥官，而是『一台还在响的收音机』。
叙事核心是陪伴：选择播什么歌、说什么话、接谁的电话，本质是在决定以什么姿态陪一座城市走完最后一夜。

## 2. 玩法结构
- 12 个回合（每 2 小时一幕，22:00 → 次日 22:00）。
- 每回合一个动作：歌曲 / 播报（安抚·中立·真相）/ 来电 / 信号 / 沉默。
- 单次游玩约 6~10 分钟；9 种结局（含 1 个隐藏结局），重玩价值来自选择而非随机。

## 3. 仿真模型
- 城市状态：hope（希望）与 mood（氛围），0~100，由动作效果累计。
- 你的精力：djStamina 0~100（初始 70）。歌曲 -3、播报 -5、来电 -4、信号 -6、沉默 +10；<25 触发疲惫提示，结局档案留痕。
- 听众：15 名角色各有心情值与喜好标签；歌曲通过标签匹配影响个体。
- 点歌联动：来电带 request 时记录 pendingRequest，下一回合放对应歌获得 +6 心情 +2 希望；否则留下一句叹息。
- 未接来电：双来电回合（T3/T6/T9/T10）未接的电话会写入错过剧情。
- 关键旗帜：lullaby / truthCount / professorMet / signalDecoded / laozhouHonored / veteranHonored / silenceCount 等驱动结局。
- 确定性：引擎无随机数，同一剧本必然同一结局。

## 4. 结局判定（9 种，按优先级）
1. 终局沉默 或 hope<20 → 尘埃
2. 终局希望 + 从未沉默 + hope≥75 → 不灭的电波
3. 终局真相 + 已解码 + 摇篮曲 → 黎明之后
4. 终局希望 + 摇篮曲 + hope≥50 → 黎明歌谣
5. 终局真相 + 已解码 → 信号
7. 终局真相 + 已解码 → 信号
8. 终局陪伴 + 摇篮曲 + 接小雨与双胞胎 → 夜莺
9. 终局陪伴 + 接老周或老兵 → 火光
10. 终局希望 + 已解码 + 无摇篮曲 → 灯塔
11. 隐藏：已集齐基础结局 + 未沉默 + 希望≥40 → 纪念日
兜底：陪伴→(hope≥50?火光:尘埃)；希望→(hope≥50?黎明歌谣:火光)；真相→(已解码?信号:hope≥50?火光:尘埃)。

## 5. 节奏设计（情绪曲线）
- 前 4 回合：建立关系（来电密集、轻音乐、点歌）。
- 第 6 回合：军队切频——外部压力第一次降临。
- 第 10 回合：FREQUENCY X——真相的诱惑与责任。
- 第 11 回合：告别来电（老周/老兵二选一）。
- 终局：希望 / 真相 / 陪伴 / 沉默，四选一对应九种结局。

## 6. 音频
- 电台底噪（白噪 + 50Hz 嗡鸣）常驻，营造收音机质感。
- 每首歌按标签选择和弦进行/波形/是否琶音，Web Audio 实时合成。
- VU 表由 AnalyserNode 实时驱动。

## 7. 测试策略
- 数据完整性：ID 唯一、来电者与点播歌曲引用存在、双来电回合存在。
- 引擎行为：回合推进、军队自动接管、X 信号锁定、点歌加成、未接来电、精力与疲惫提示。
- 九种结局分别用脚本化剧本验证可达性。
- 确定性：同剧本两次游玩结果 deepStrictEqual。
