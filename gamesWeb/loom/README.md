# LOOM · 织机编程

> 写一份织造程序，让 1804 年的打孔卡片织机把它变成布。

这不是画图工具，而是一台**可编程织机**。你写的是织造工艺本身 —— 穿综、提综、踏综，或者直接给出每一纬的提花计划；程序跑起来就是一块布，布上的每一根线都能追回程序里的某一行。

纯前端、零第三方依赖、零构建：双击 `start.bat`，或者直接用浏览器打开 `index.html`。

---

## 为什么是织机

1804 年，Jacquard 把提花图案打在卡片上，织机就能自动织出任意图案 —— 这是人类第一台**用打孔卡片编程**的机器。卡片 → Babbage 的分析机 → Hollerith 的制表机 → 电子计算机。

LOOM 里的 `liftplan` 就是那张卡片：一个 `0/1` 矩阵，`1` 表示这根经线被抬起。你在屏幕上敲下的每一行，都是一百多年前织工手里那根通丝。

所以这个项目做的不只是"织一块好看的布"，而是把**编程史的起点**搬回屏幕上：织机是硬件，卡片是程序，布是输出。

## 界面

```
┌──────────────┬───────────────────────────┬────────────────┐
│ 织造程序      │  织物                      │  分析           │
│ （带行号）     │  写实织物 / 组织图          │  组织识别        │
│ 实时诊断      │  滚轮缩放 · 拖拽平移         │  循环与浮长      │
│              │  手绘提花                   │  结构提醒        │
│              ├───────────────────────────┤  织物规格        │
│              │  打孔卡片链 / 织机 / 织造图   │                │
└──────────────┴───────────────────────────┴────────────────┘
```

- **织造程序**：`Ctrl+Enter` 运行，输入时自动重织并实时报错（行号 + 原因）。
- **写实织物**：每一格画的是"谁压在表面"，经浮点带投影，纱线有粗细与明暗抖动。
- **组织图**：织工看的黑白平涂图，经浮点 = 经纱色。
- **打孔卡片链**：每一纬一张卡，实心圆 = 抬起的经线，左侧是送卡齿轮孔。
- **织机**：俯视动画 —— 开口 → 投梭 → 打纬，布从织口一纬一纬长出来（可选音效）。
- **织造图**：经典四象限（穿综 / 提综 / 踏综 / 织物）。
- **手绘提花**：勾上之后直接在布面上涂改，松手时程序会被自动改写 —— **画布就是代码**。

## 织造程序语法

数字一律从 1 开始数（和第几根经线、第几片综框的说法一致）。

```
# 井号后面是注释
title 2/2 斜纹
warp 32 / weft 32        # 经线数 / 纬线数
shafts 4 / treadles 4    # 综框数 / 踏杆数

threading 1 2 3 4        # 穿综：第几根经线穿在第几片综框
tieup                    # 提综：每根踏杆抬起哪些综框
  1: 1 2
  2: 2 3
  3: 3 4
  4: 4 1
treadling 1 2 3 4        # 踏综：每一纬踩哪根踏杆

warp-yarn #c8623c        # 经纱颜色（也支持 茜红 / 靛蓝 这样的中文色名）
weft-yarn #2f4f63
```

也可以跳过提综 / 踏综，直接写提升计划（打孔卡片本身）：

```
warp 12 / weft 12
liftplan
  1: 5 6
  2: 4 7
  3: -
```

| 指令 | 说明 |
| ---- | ---- |
| `title` / `名称` | 织物名字 |
| `warp` / `ends` / `经线` | 经线数 |
| `weft` / `picks` / `纬线` | 纬线数 |
| `shafts` / `综框` | 综框数 |
| `treadles` / `踏杆` | 踏杆数 |
| `threading` / `穿综` | 每根经线的综框号，不足时按织造惯例循环补齐 |
| `tieup` / `提综` | 每根踏杆抬起的综框，可用 `1 2 \| 2 3` 单行写 |
| `treadling` / `踏综` | 每一纬踩的踏杆号 |
| `liftplan` / `提升计划` | 逐纬给出抬起的经线号，`-` 表示空 |
| `warp-yarn` / `weft-yarn` | 纱线颜色（`#rgb` / `#rrggbb` / 中文色名） |

小技巧：`1-4` 等于 `1 2 3 4`；`warp 32 / weft 32` 可以写在一行；穿综 / 踏综给少了会自动循环补齐。

## 组织识别

程序会从织物矩阵里**反推**组织，而不是读你写的草稿。算法分四步：

1. **最小循环**：先求织物矩阵的真实周期，把它压成一个循环单元（例如 32×32 的平纹其实是 2×2）。
2. **规则组织**：如果每一纬恰好一段经浮、段长恒定、每纬位移恒定，就是一个规则组织 ——
   - 2 枚 + 经浮 1 → **平纹**
   - 位移 1 → **斜纹**（按 经浮/纬浮 给出 2/2、1/3、3/1 这样的名字和斜向）
   - 经浮 = 1 或 R−1 且位移 ≠ ±1 且与 R 互质 → **缎纹**（给出枚数与飞数）
3. **方块棋盘**：`平纹 / 方平 / 横条纹 / 纵条纹 / 格纹` 其实是同一个家族 —— 循环单元等于 `floor(p/b) + floor(e/a)` 的奇偶性，程序会把 a、b 解出来。
4. **镜像轴**：折返点斜纹（人字纹）存在一条镜像轴 `tile[p][e] === tile[p][s−e]`，普通斜纹没有 —— 这是区分两者的判据。

最后再和**纹样库**做精确比对（允许循环平移），命中就报出库里的名字。识别结果会和"最长浮长""经纬面比例"一起显示在右侧。

## 内置纹样库（12 种）

| 纹样 | 组织 | 一句话 |
| ---- | ---- | ---- |
| 平纹 | 2 枚 | 一上一下，最基础也最结实 |
| 方平组织 | 4 枚 | 两根经纱并列浮起，表面成方格 |
| 2/2 斜纹 | 4 枚 | 牛仔布的组织 |
| 1/3 斜纹 | 4 枚 | 纬面斜纹 |
| 3/1 斜纹 | 4 枚 | 经面斜纹，光泽强 |
| 点斜纹（人字） | 4 枚 / 6 枚循环 | 斜向在折返处反转 |
| 5 枚经面缎纹 | 5 枚 / 飞数 2 | 平滑有光泽 |
| 5 枚纬面缎纹 | 5 枚 / 飞数 2 | 纬纱占表面 |
| 8 枚经面缎纹 | 8 枚 / 飞数 3 | 浮长更长、更亮也更娇气 |
| 纵条纹 | 2 枚 | 经向条纹 |
| 菱格提花 | 提升计划 | 逐点控制每根经线 |
| 双色平纹 | 2 枚 | 组织不变，只换纱线颜色 |

纹样库里的每一条**都是用同一套 DSL 写的**，可以被解析器读回来，也能一键加载到编辑器里继续改。

## 织物规格

右侧面板会把组织换算成纺织工程上的实际指标：

- **克重** `g/m² = (经密 × 经纱 tex + 纬密 × 纬纱 tex) / 10`
  （1 tex = 每 1000 米 1 克，所以每厘米 n 根、每米 100n 根 → n·tex/10）
- **纱线直径** `d(mm) = 0.03568 × √(tex / ρ)` —— 由 `A = tex/(ρ·1000) mm²` 反推截面圆直径，
  棉 ρ ≈ 1.5 g/cm³（20 tex 棉纱 ≈ 0.13 mm，和实际吻合）
- **织物覆盖率** `1 − (1 − n经·d经/10)(1 − n纬·d纬/10)` —— 两个方向互相独立地遮挡，得到真正被纱线盖住的面积比
- 每米经纱 / 纬纱根数、纬密比

## 测试

```
node test/run.js        # 123 项：引擎 / DSL / 纹样库 / 规格计算 / 渲染像素验证
node test/smoke-ui.js   # 界面冒烟：12 个纹样 × 全部交互路径
```

两处值得一提：

- **渲染是逐像素验证的**：`test/run.js` 会用 `tools/render-png.js` 里的软件光栅化器把织物真的画出来，然后采样每一格中心像素，检查它的颜色是否真的是该格对应纱线的颜色（要求 ≥ 97% 一致）。这比"函数没抛异常"强得多。
- **界面是驱动出来的**：`smoke-ui.js` 用浏览器桩加载全部前端文件，然后模拟"选纹样 → 改配色 → 缩放拖拽 → 手绘提花 → 切标签 → 导出 → 写坏程序"这一整条真实路径。

## 技术说明

**为什么提升计划和织物矩阵是同一个东西。**
被抬起的经线压在刚打入的纬线之上，所以"这一纬哪些经线抬起"直接就是"这一纬哪些格子是经浮于表"。于是：

```
liftplan[p][e] = tieup[treadling[p]][threading[e]]
drawdown[p][e] = liftplan[p][e]
```

这也意味着**任何图案都能织出来**：只要逐纬给出提升计划，不受综框数量限制 —— 手绘提花之所以可行，就是因为这一点。

**浮长为什么要按环算。**
织物是循环的，一段浮长如果跨过循环边界，它在实际布面上是连续的。所以浮长统计把每一行/列当作环来处理（`[1,0,0,1]` 是**一段长 2** 的浮长，不是两段长 1）。

**渲染热路径为什么要按"纱线"而不是"交织点"来算。**
一根纱线的抖动、颜色、渐变只跟它自己的索引有关，跟它和谁交织无关。早期版本在每个交织点上重新调用
`shade()`（字符串解析 + 十六进制格式化）并新建一个 `LinearGradient`，400×400 的织物一帧要 350ms 以上。
现在每根经线/纬线在一帧里只计算一次颜色与渐变，然后被整列/整行复用；大面积织物自动关闭投影与纤维噪点。
实测（headless Edge，900×900 画布）：

| 场景 | 优化前 | 优化后 |
| ---- | ------ | ------ |
| 400×400 随机提花 · 格边长 8px | 356 ms/帧 | **34 ms/帧** |
| 400×400 随机提花 · 格边长 1.5px | 91 ms/帧 | **47 ms/帧** |
| 32×32 斜纹 · 格边长 13px | 5.4 ms/帧 | **3.5 ms/帧** |

组织识别同样加了护栏：镜像轴检测最坏是 `O(w·h·w)`，先做便宜的比例排除再算；方块候选限制在 16 根纱线以内。
一个 256×256 的病态循环单元（几乎全经面）从 292ms 降到 **5ms**，并有回归测试守着。

**为什么自带一个软件光栅化器。**
`tools/render-png.js` 实现了 `fabric.js` 需要的那一小撮 Canvas 2D API（fillRect、线性渐变、平移、透明度、直线、多边形填充），于是**同一份渲染代码**既能在浏览器里跑，也能在命令行里导出 PNG —— 顺带让渲染有了可自动化验证的像素级断言。

## 已知限制

- 综框上限 32、踏杆上限 32、织物上限 512 × 512（再大就不是织造，是像素画了）。
- 组织识别只覆盖规则组织、方块棋盘家族与镜像斜纹；复杂提花会诚实地报"不规则 / 复合组织"。
- 织机动画是俯视示意，不做真实的综丝运动学与张力计算。
- 浮长 > 5 会给出"容易勾丝"的提醒，但不会阻止你织 —— 有些织物就是要长浮长。
