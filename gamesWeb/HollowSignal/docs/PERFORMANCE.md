# 性能文档

## 目标

- 目标帧率：60 FPS。
- 最低可接受帧率：30 FPS；通过动态分辨率避免持续低于 30。
- 分辨率基线：1280×720 与 1600×900。
- 自动化采样环境：Windows、Edge 无头浏览器、WebGL2、1280×720。

无头浏览器不受显示器垂直同步限制，因此采样中的“260 FPS”不是实际显示器帧率；性能判断应看帧时间、p95、绘制调用、三角形数量与动态缩放行为。

## 渲染架构

### 静态合批

`StaticBatch` 将墙体、地面、天花板、装饰条、铆钉、管道和大部分静态道具按材质合并为少量网格，避免每个小物件产生独立绘制调用。`BaseLevel.addStaticBox`、`addStaticCylinder` 等接口返回的静态几何最终都进入批处理。

### 烘焙光照

`BaseLevel.finalize()` 在关卡构建完成后烘焙静态顶点照明，并将结果合入静态批次。运行时只保留少量动态灯、手电筒、阵列脉冲与追逐灯，降低逐帧光照成本。

### 可见性剔除

- `DetailOccluder` 根据碰撞体和相机位置隐藏被墙/大型物体遮挡的细节。
- 斜向剔除距离（`obliqueCullDistance`）随画质档位调整。
- 远处道具使用 `LOD`；例如泵组有高、中、低三级，距离阈值分别约为 0、10、22 米。
- 静态批次只提交真实可见的几何；烟尘粒子采用对象池，粒子系统关闭视锥剔除以避免出生点误判。

### 动态分辨率

`RenderPipeline` 以 1.25 秒为窗口采样平均帧率：

- 平均低于 52 FPS 时，按 0.08 步长降低渲染缩放，冷却 2.2 秒。
- 平均高于 58 FPS 时，按 0.04 步长回升，冷却 4 秒。
- 每个档位有最低动态缩放：低 0.62、中 0.70、高 0.78。
- 画质设置改变时会重建渲染目标并应用新的渲染缩放。

### 阴影与后处理

- 阴影贴图：低 512、中 1024、高 2048；三档都保留阴影，但分辨率不同。
- MSAA：低关闭、中 2×、高 4×。
- 后处理在单个全屏四边形上完成色彩分级、暗角、颗粒与轻微色差；不额外引入多重渲染通道。
- 渲染器使用 `powerPreference: 'high-performance'`，关闭不必要的 stencil 与 preserveDrawingBuffer。

### 音频流

环境声按章节从 `assets/audio/ambience/<track>/` 以 WAV 分块加载，并使用 `Accept-Ranges` 支持流式播放。不会在启动时一次性解码全部章节音频。

## 实测结果

采样命令：

```powershell
node tools/diag-perf.mjs
```

采样条件：1280×720、无头 Edge、关闭自适应缩放、每个场景约 2.6 秒。结果写入 `qa-output/perf-final.log`。

| 场景 | 绘制调用 | 三角形 | p95 帧时间 | >25ms | >33ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第一章 检修隧道 | 190 | 61,573 | 3.9ms | 0 | 0 |
| 第二章 泵层 | 343 | 109,342 | 3.9ms | 0 | 0 |
| 第三章 船员层 | 375 | 69,547 | 3.9ms | 0 | 0 |
| 第四章 共振展厅 | 125 | 53,265 | 3.9ms | 0 | 0 |

高画质下第二章的峰值为 345 次绘制、109,462 个三角形。无头采样平均约 260 FPS，p95 约 3.9ms；中画质第二章出现一次 15.4ms 的长帧，但没有超过 25ms 或 33ms 的样本。该结果说明场景复杂度与帧时间有充足余量，但不能替代真实显示器上的垂直同步测量。

冒烟测试结束时的中画质样本为：

```text
final draw calls=271, triangles=107870, quality=medium
```

## 性能预算与瓶颈

- **绘制调用**：当前峰值约 375，主要来自不同材质、动态灯、交互物与细节批次；静态合批后仍保持较低水平。
- **三角形**：峰值约 11 万，远低于现代桌面 GPU 的负担；复杂道具通过 LOD 降级。
- **填充率**：高画质 1.5 像素比与 4× MSAA 是主要 GPU 成本；动态分辨率会优先降低渲染缩放。
- **CPU**：每帧的碰撞、交互检测与聆听者寻路为轻量逻辑；音频流在后台解码，不阻塞主线程。
- **内存**：纹理与音频按需缓存；切换章节时释放上一章的场景资源。

## 性能验证建议

1. 在目标机器上以 1600×900 高画质游玩第一章至第四章。
2. 观察 HUD 调试帧率（`window.__hollow` 调试模式）或浏览器 Performance 面板。
3. 在第二章泵层与第三章追逐段确认没有持续低于 30 FPS。
4. 切换低/中/高画质，确认分辨率、MSAA、阴影和粒子密度变化。
5. 如出现持续低帧，优先检查浏览器是否使用软件渲染、是否禁用了硬件加速，以及是否同时开启了其他 WebGL 页面。

## 已知限制

- 无头 Edge 的帧率不代表真实垂直同步表现。
- 高端显卡上无头采样会被 260 FPS 左右的上限截断，无法用于比较绝对性能。
- 动态分辨率只在帧率持续低于阈值时介入；短时卡顿仍可能被感知。
- 极端低端集显在 1600×900 高画质下可能需要手动切到中或低画质。
