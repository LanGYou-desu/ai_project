# THE VANISHED · 林薇失踪事件 —— 桌面悬疑事件

> 一场**实时上演**的桌面惊悚剧。你在凌晨接班时发现同事林薇失踪，
> 接下来约 31 分钟里，线索通过 **真实的 Windows 通知**、**真实的磁盘证据文件**
> 和模拟聊天软件陆续送达。错过通知就可能错过线索——结局由你的"在场度"决定。

- 类型：实时桌面悬疑剧（单机 · 真实时间线）
- 技术栈：Node.js（零第三方依赖）+ 原生 HTML/CSS/JS + PowerShell（真实系统通知）
- 时长：一局约 **31 分钟真实时间**（25 个事件；剧情内时钟 00:00 → 00:40，线索里的
  23:47 – 23:58 是林薇失踪当晚的**回溯时间**）；
  界面右上角可切换 1x / 4x / 8x / 16x 倍速（接口允许 0.5x – 100x）
- 内容量：**5 种结局 · 3 个检查点 · 7 份证据文件**，满分 **16 分**
- 世界是固定的，只有你的注意力不同 → 结局不同，可随时重开

## 玩法

1. 双击 `start.bat`（或 `node server.js`），浏览器会自动打开 http://127.0.0.1:8768 ，游戏立即开始。
2. **真实 Windows 通知**会直接弹到屏幕右下角——那是线索的一部分。
3. 证据文件会真实写入 `evidence/` 目录，可以随时用资源管理器打开查看。
4. 聊天窗口收到林薇的加密消息（base64），可以自己解码。
5. 三个检查点决定你的"注意力"评分；最终选择 + 注意力 = 5 种结局之一。

## 结局

| 结局 | 判定条件（满分 16） | 简述 |
| ---- | ---- | ---- |
| 真相大白 `perfect` | 最终行动正确且注意力 ≥ 11 | 救出林薇，老周落网 |
| 营救成功，真凶在逃 `good` | 最终行动正确且注意力 ≥ 8 | 救出林薇，但证据不足 |
| 迟到的救援 `okay` | 行动正确且注意力 ≥ 4；或行动错误但注意力 ≥ 8 | 人救出来了，晚了点 |
| 一夜之差 `bad` | 行动错误且注意力 4 – 7 | 第二天清晨才发现她 |
| 沉默的夜班 `worst` | 行动错误且注意力 ≤ 3 | 三天后才发现她…… |

阈值常量定义在 `lib/engine.js` 的 `THRESHOLDS`；5 种结局的标题与正文（`lib/story.js` 的 `ENDINGS`）
随 `/api/state` 的 `endingTitle` / `endingText` 下发给前端，前端不再维护第二份文案。

## 计分

| 项目 | 分值 |
| ---- | ---- |
| 查看证据文件 | 每份 +1，上限 7（每份只计一次） |
| 检查点答对 | 每个 +2（共 3 个检查点） |
| 最终行动正确 | 检查点 +2 之外**额外 +3**（即行动正确共 +5） |
| 满分 | 7 + 2×3 + 3 = **16** |

- 检查点只有在**对应事件出现之后**才能作答，且无效选项不会消耗作答机会。
- 事件结束后分数冻结：`/api/state` 的 `attention` 与结局记录的 `finalScore` 始终一致。
- 计分常量见 `lib/engine.js` 的 `SCORE`。

## 技术要点

- **时间线引擎**：真实时间推进（`accumulatedMs + dt × speed`），事件按剧本投递，存档持久化。
  单次 tick 最多补记 5 秒真实时间——合盖休眠或系统时钟前跳时会**暂停**而不是瞬间播完整局。
- **真实通知**：`notify.ps1` 通过 Windows Toast API（WinRT）弹出系统通知，失败自动回退到消息框。
  通知正文以 **base64** 传给 PowerShell（`-TitleB64` / `-TextB64`），内容不进入命令行解析。
- **真实证据**：`evidence/` 目录中的 7 份文件由服务器按时间线真实生成（txt / csv），
  写入使用「临时文件 + 原子替换」，不会读到半截内容。
- **存档自愈**：`state.json` 被手工改坏、被旧版本写入或截断时会被校正成合法状态（丢弃未知事件、
  夹紧倍速），不会让服务器崩掉。

## 环境变量

| 变量 | 默认值 | 说明 |
| ---- | ---- | ---- |
| `PORT` | `8768` | 监听端口（非法值会回退到 8768） |
| `HOST` | `127.0.0.1` | 监听地址，默认只监听本机 |
| `VANISHED_DATA_DIR` | 项目根目录 | `evidence/` 与 `state.json` 的存放目录（测试 / 多开用） |
| `VANISHED_SPEED` | `1` | 启动倍速，等价于界面上的倍速下拉 |
| `VANISHED_NO_NOTIFY` | 未设置 | 设为 `1` 时不弹系统通知（界面内仍显示通知记录） |
| `VANISHED_NOTIFY_TIMEOUT_MS` | `30000` | 通知进程超时被杀掉的时间（消息框回退会阻塞） |
| `NO_BROWSER` | 未设置 | 设为 `1` 或加 `--no-browser` 参数则不自动打开浏览器 |

## HTTP 接口

改动状态的接口都要求 `Content-Type: application/json`（跨站表单发不出这个头，因此挡得住
对 localhost 的 CSRF 式提交）：

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/api/state` | 完整状态：`elapsed` / `totalSeconds` / `attention` / `delivered` / `checkpoint` / `ended` / `endingTitle` / `endingText` / `finalScore` |
| POST | `/api/answer` | `{cid, option}`，返回 `{ok, correct, correctOption, explain, score}`；未出现的检查点、无效选项返回 400 |
| POST | `/api/view` | `{file}`，返回证据正文并计分 |
| POST | `/api/speed` | `{speed}`，夹紧到 0.5 – 100 |
| POST | `/api/restart` | 重开一局；带 `?fresh=1` 时同时清空 `evidence/` |

其他安全约束：请求体上限 64 KB（超出返回 413）、静态服务与 `/api/view` 的路径穿越一律拒绝、
默认只监听 `127.0.0.1`。

```
cd games-desktop/the-vanished
node test/run.js      # 或 npm test
```

**42 项测试**，覆盖：剧情数据完整性（25 个事件 / 5 个结局 / 7 份证据 / 3 个检查点 / 正确答案
必须在选项内）、时间线投递与不重复投递、倍速夹紧、持久化、时钟跳变与回拨、损坏存档自愈、
计分与检查点（未出现不能答 / 无效选项不消耗 / 不能重复答 / 结算后冻结）、5 种结局判定与阈值、
重开、通知参数 base64 编码与非 Windows 降级，以及服务器冒烟（畸形请求行不崩、超大请求体 413、
静态与 `/api/view` 路径穿越、POST 必须带 JSON、倍速夹紧、证据文件落在数据目录内）。

## 已知限制

- 系统通知只在 Windows 上生效；其他平台会自动降级为「只在界面里显示通知记录」，不会报错。
- Toast 失败时会回退到消息框，而消息框会阻塞直到被点击；30 秒后进程会被杀掉（见
  `VANISHED_NOTIFY_TIMEOUT_MS`）。
- 端口被占用时服务器会打印提示并退出，不会自动换端口。
- 界面每秒半轮询一次 `/api/state`（不是 WebSocket / SSE）；对单机小游戏足够，但实时性依赖轮询间隔。
